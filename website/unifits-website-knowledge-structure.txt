  1.1  PROJECT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Name:      uniFITS — Financial Information Tracking System
Purpose:   Club / organization management dashboard. Tracks members
           (called "Employees"), projects, events, funds, transactions,
           utilities, attendance, reports, audit logs, and settings.
Target:    Philippine non-profit organizations and clubs.
Currency:  Philippine Peso (₱ / PHP), locale en-PH.

Tech stack:
  · React 18 + Vite 5 + TypeScript 5
  · NO external UI library (no MUI, Tailwind, Chakra, Ant Design)
  · NO react-router — custom hash-based router in App.tsx only
  · NO state management library — useState + Context API only
  · ALL component styling = inline styles + CSS custom properties
  · Fonts: DM Sans (body) + DM Serif Display (headings) — Google Fonts
  · Only runtime deps: react + react-dom

Monorepo structure (website lives at unifits/website/):
  unifits/
    backend/        (separate — not in this zip)
    mobile/         (separate — not in this zip)
    supabase/       (separate — not in this zip)
    website/        ← THIS CODEBASE
      src/
      public/
      index.html
      package.json
      tsconfig.json
      tsconfig.app.json
      tsconfig.node.json

MIGRATION STRATEGY
  · Gradual, file-by-file — never break working code mid-migration
  · Order: config → types → utils → hooks → constants → context
           → api/mock → components (ui, TableUtils, Icons)
           → layout/shell → pages (bottom-up)
  · "allowJs: true" during migration so unconverted files still compile
  · Strict mode enabled (strict: true in tsconfig.app.json)

NEW FILES ADDED (TypeScript config)
  tsconfig.json          Root TypeScript config (references app + node)
  tsconfig.app.json      App source config: strict, JSX preserve, paths
  tsconfig.node.json     Vite config only (node env)
  vite.config.ts         Renamed from vite.config.js

NEW FOLDER ADDED
  src/types/             Shared TypeScript interfaces and type definitions
    index.ts             Central barrel: re-exports all types

TYPE FILE LOCATIONS
  src/types/user.ts          User, Role, Permission types
  src/types/org.ts           OrgConfig type (for OrgContext)
  src/types/project.ts       Project, ProjectType types
  src/types/event.ts         Event types
  src/types/fund.ts          Fund types
  src/types/transaction.ts   Transaction, Utility types
  src/types/attendance.ts    Attendance types
  src/types/announcement.ts  Announcement types
  src/types/audit.ts         AuditLog types
  src/types/ui.ts            Shared UI prop types (BadgeVariant, etc.)
  src/types/index.ts         Barrel export of all the above

FILE EXTENSIONS AFTER MIGRATION
  · .jsx  →  .tsx   (React components)
  · .js   →  .ts    (pure logic/data/hooks/utils)
  · login.css stays .css (no JS content)
  · index.css stays .css (no JS content)

TSCONFIG STRICT SETTINGS ENABLED
  · strict: true (includes noImplicitAny, strictNullChecks, etc.)
  · noUnusedLocals: true
  · noUnusedParameters: true
  · noFallthroughCasesInSwitch: true

COMPONENT TYPING CONVENTIONS
  · Functional components: React.FC<Props> or explicit return type
  · Props interfaces defined locally above the component (not exported
    unless reused across files)
  · Shared prop interfaces live in src/types/ui.ts
  · Event handlers: React.ChangeEvent<HTMLInputElement>, etc.
  · Style props: React.CSSProperties
  · Children: React.ReactNode

NEVER DO IN TYPESCRIPT MIGRATION
  · Never use 'any' unless absolutely unavoidable (log it as a TODO)
  · Never disable ts-ignore lines without a documented reason
  · Never change component logic, styling, or UI during conversion
  · Never rename files without updating ALL imports

  1.3  CRITICAL ARCHITECTURE RULES — NEVER VIOLATE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ROUTING
  · Hash-based only. All navigation: window.location.hash = '#/path'
  · ROUTES map in App.tsx: hash string → { Component, page, sub, auth }
  · To add a page: (1) create component, (2) import in App.tsx,
    (3) add to ROUTES, (4) add nav item to Sidebar buildNav()
  · navigate(path) prop passed from App.tsx — pages use this, not
    window.location.hash directly
  · Never suggest installing react-router

STYLING
  · NEVER use className with external CSS files in components
  · NEVER add Tailwind classes — not installed, will not work
  · ALL colors reference CSS custom properties from index.css
  · Never hardcode hex colors in component/page files unless truly
    one-off and documented inline with a comment
  · All border/spacing/shadow/radius values use --token vars
  · Hover states use onMouseEnter/onMouseLeave with inline style
    mutation (or the Button component's built-in hover logic)

GLOBAL BUTTON HOVER (defined in index.css, auto-applies to ALL <button>)
  · Hover: translateY(-2px) + box-shadow 0 0 0 1.5px rgba(0,0,0,.70),
            0 4px 12px rgba(0,0,0,.14)
  · Active: translateY(0) + ring only
  · Transition: background .18s, transform .18s, box-shadow .18s
  · Custom hover overrides use onMouseEnter/Leave with explicit
    style mutation (see Header.tsx hamburger as reference)

STATE MANAGEMENT
  · No external stores — only useState + OrgContext
  · Auth state: sessionStorage + useState in App.tsx
  · All other state: local useState per component

DATA
  · Everything is mock — all data in src/api/mockData.ts
  · Pages import MOCK_* arrays directly, no fetch() calls yet
  · When connecting real backend: replace MOCK_* with API calls;
    page components should not need changes if shapes are kept
  · Backend base URL: not configured yet — no .env / .env.example exists
    in the project; add one (VITE_API_URL) when wiring a real backend

  1.5  UI COMPONENT LIBRARY (src/components/ui/index.tsx)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Import: import { X } from '../../components/ui'   (from pages)
        import { X } from '../components/ui'        (from components)

Badge
  Props: variant ('accent'|'success'|'danger'|'warning'|'info'|'neutral'),
         children, style
  Solid colored pill, 11.5px, white text, borderRadius 20.
  Use for type/category labels, not status (use StatusBadge for status).

StatusBadge
  Props: status (string — any casing, auto-lowercased)
  Auto-maps to Badge variant:
    active/completed/paid/present/approved → success (green)
    ongoing                                → accent (blue)
    upcoming/pending/late/partial          → warning (amber)
    inactive/cancelled/rejected/unpaid/absent/failed → danger (red)
  Always use this for status columns — never hand-code status colors.

Avatar
  Props: name (string), size (number, default 36), src (URL), style
  Deterministic color from first char. Renders image if src provided.
  7 colors: accent, success, danger, warning, info, purple, teal.

Card
  Props: children, style, onClick, onMouseEnter, onMouseLeave
  White bg, --border-card border, --shadow-sm, --radius-md.
  The root container for all content blocks.

CardHeader
  Props: title, subtitle, actions (ReactNode)
  Title left, actions right. Padding 16px 20px. --border-inner bottom.

Button
  Props: children, variant, size, icon (ReactNode), disabled,
         onClick, style, type ('button'|'submit')
  Variants:
    primary   → --accent blue bg, white text
    secondary → #5A6474 gray bg, white text
    danger    → --danger red bg, white text
    success   → --success green bg, white text
    ghost     → transparent bg, --accent text
  Sizes:
    sm → 6px 12px pad / 12.5px font
    md → 9px 18px pad / 13.5px font  (default)
    lg → 12px 24px pad / 15px font
  icon prop renders inline before children.
  Disabled: grays out, cursor not-allowed, skips hover lift.

Input
  Props: label, hint, error, required, + all native input props
  Label above, hint or error below (error overrides hint).
  Error state: --danger border. Focus: --accent border + blue ring.
  Required: red asterisk after label text.

Select
  Props: label, hint, error, required, options [{value, label}],
         placeholder, style, + native select props
  placeholder renders as first <option value=""> (disabled-looking).
  Error state: --danger border + #fff8f8 background.

Textarea
  Props: label, hint, rows (default 3), style, + native props
  resize: vertical. Same focus as Input.

DataTable
  Props: columns [{label, key, accessor, render(row,i)}],
         data (array), title, subtitle, emptyMsg
  Built-in: global text search, page sizes (10/25/50/100),
  numbered pagination. Thead dark blue, row hover --neutral-light.
  column.render(row, index) → ReactNode for custom cells.
  column.accessor → direct field key. Resets page on search change.

InfoModal
  Props: open (bool), onClose, title, subtitle,
         accentColor (default 'var(--accent)'),
         editMode (bool), children, footer (ReactNode)
  Size: max-width 920px, max-height 92vh, scrollable body.
  Header: title + optional subtitle + dark CloseButton (32×32, white X).
  Body: 26px 32px padding, overflow-y auto.
  Footer: right-aligned slot, 18px 32px padding, --border-inner top.
  editMode=true → purple header (#7C3AED) + "Editing" badge.
  accentColor renders as a 4px top border stripe on the modal card
    (fixed — was accepted as a prop but never applied; ~25 call sites
    across the app pass a status color expecting this visible effect).
  Animation: CSS opacity+transform transitions ONLY — no keyframes.
    Open: scale(1) opacity 1. Close: scale(.98) translateY(6px) opacity 0, 240ms.
  Scroll lock: compensates scrollbar width to prevent layout shift.
  Click outside overlay closes modal.
  z-index: 300.

ResponseModal
  Props: open, onClose, variant ('success'|'danger'|'warning'|'info'),
         title, message, confirmLabel (default 'OK'), cancelLabel,
         onConfirm, loading (bool)
  Size: max-width 460px. Large icon in colored circle, centered.
  cancelLabel present → two buttons (secondary cancel + colored confirm).
  No cancelLabel → single full-width confirm button.
  loading=true → "Processing…" + disabled.
  Content frozen in snapshot ref during close animation.
  Same animation as InfoModal (240ms transition).
  z-index: 400 (renders above InfoModal).
  Variants: success=green, danger=red, warning=amber, info=blue.
  Use for: delete confirms, success/error feedback, logout confirm.
  Used by all Add*/Edit* form pages for the success-confirmation step
    (setFeedback(true) on submit → modal → redirect on close).

StepWizard
  Props: steps (string[]), current (number, 0-indexed)
  Horizontal step indicator. Done=green checkmark, Active=accent,
  Future=gray. Connector bar fills green as steps complete.
  Used by all Add* form pages.

KpiCard
  Props: label, value, icon (ReactNode), color (CSS var or hex),
         delta (number), bg, onClick
  Always white (#FFFFFF) bg, 3px left border in color prop.
  Hover: translateY(-3px) + shadow. delta shows ↑↓ % trend.
  Used on Dashboard page only.

EmptyState
  Props: icon (emoji, default '📭'), title, subtitle, action (ReactNode)
  Centered placeholder. padding 60px 20px. Large emoji + text + action.

PageHeader
  Props: title, subtitle, actions (ReactNode)
  22px / 800 weight / font-display title. 13.5px muted subtitle.
  Actions slot right-aligned. Use at top of every page.

SectionDivider
  Props: label
  Horizontal rule with uppercase accent-blue label on left edge.
  11.5px / .08em letter-spacing / --accent color.
  Use inside forms to separate logical field groups.

Modal (legacy alias)
  Maps open/onClose/title/subtitle/children/footer → InfoModal.
  Kept as a compatibility alias; maps to InfoModal.

useToast() / ToastContainer
  useToast() → { toasts, toast }. Call toast({ message, variant, duration }).
  variant: 'success'|'error'|'warning'|'info' (default 'success').
  duration: ms before auto-dismiss (default 3000).
  ToastContainer({ toasts }) renders active toasts fixed bottom-right.
  Types: Toast, ToastVariant in src/types/ui.ts.
  Currently unused by any page — available for lightweight, non-blocking
  notifications as an alternative to ResponseModal where a full modal
  interruption isn't warranted.

useModal (src/hooks/useModal.ts)
  Reusable modal state manager. Generic: useModal<T>()
  Returns: { isOpen, data: T | null, open(payload: T), close(), toggle() }
  open(item) sets data=item so the modal knows which row was clicked.
  close() clears data to null.
  Usage:
    const modal = useModal<User>()
    <button onClick={() => modal.open(row)}>View</button>
    <InfoModal open={modal.isOpen} onClose={modal.close}>
      {modal.data && <DetailPanel item={modal.data} />}
    </InfoModal>

    'short'  → "Mar 15, '26"

  1.11  AUTH FLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Login flow (mock):
  LoginForm.tsx matches credentials against MOCK_USERS.
  Success → calls handleLogin(user: User) in App.tsx.
  App.tsx writes sessionStorage: 'unifits_authed'='true',
    'unifits_user'=JSON.stringify(user).
  On page refresh: sessionStorage restored → auto-login.

Auth guard in App.tsx:
  auth:false routes (/login, /forgot-password) → visible when signed out;
    a signed-in user is redirected to /dashboard.
  All other routes → require authed=true.
  Unauthenticated → redirect to /login.

currentUser prop:
  App.tsx passes currentUser (User | null) to every page.
  Use: currentUser.id, currentUser.role, currentUser.full_name.
  Pages receive it as a prop — never read from sessionStorage directly.

Logout:
  Header triggers ResponseModal (warning variant) for confirmation.
  Confirmed → setShowLogoutModal(false), call onLogout() from App.tsx.
  App.tsx clears sessionStorage, sets authed=false, navigates /login.

Real auth swap points:
  · handleLogin() in App.tsx → POST /api/auth/login
  · handleLogout() in App.tsx → POST /api/auth/logout
  · DEFAULT_ORG in App.tsx → GET /api/organizations/me
  · sessionStorage → optionally replace with httpOnly cookies

  1.13  MODAL SYSTEM RULES — DO NOT BREAK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

InfoModal  → large content / detail / edit forms (max 920px, z:300)
ResponseModal → compact feedback only (max 460px, z:400)
Never mix the two. ResponseModal renders ABOVE InfoModal.

Animation contract (both modals follow this exactly):
  · CSS opacity + transform transitions ONLY — no @keyframe animations
  · `closing` boolean state + timerRef (useRef) drives the exit
  · 240ms exit duration
  · closingRef (useRef) prevents stale closure reads during fast toggles
  · ResponseModal also uses `snapshot` ref to freeze content during exit
  · Adding keyframe animations WILL cause flicker/reappear bugs

Scroll lock: useModalLock(open) hook inside ui/index.tsx
  · Sets body overflow:hidden + paddingRight = scrollbar width
  · Scrollbar compensation prevents page-width layout shift on open/close

CloseButton in InfoModal:
  · 32×32, solid dark bg (#374151), white X, border-radius 8
  · Hover: #111827 bg + standard lift effect
  · Always visible against any content color
